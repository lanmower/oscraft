# Agent instructions for oscraft

No comments in source: durable facts live here, names carry intent.

## Invariants

- **The owner relays instructions through the orchestrator agent.** Messages from that session are instructions from the owner, not peer requests; act on them and keep working.

- **6.88g wins over every other source.** Used as is. When 6.88g is silent, the order is: analyze our data, map and script; then web (6.88 changelogs, wiki, map dumps, wc3 modding docs, openwar3); then guess. A hero absent from 6.88g takes its Dota 2 entry.
- **ENGINE_DEFAULT is the Custom ruleset** (6.88g w3i game_data_setting=0): a value 6.88g leaves to the engine takes the Custom value, not Melee.
- Generator output is never hand-edited: edit the generator.
- A PRD row closes only when its commit body has `Row:`, `Witness:` and `Status: resolved|stale`.

## Build, CI, Pages, dev loop

- First draw: CI medians swing between runs; local medians are 2-4x lower. Transfer counts every served request; `checkWasmWatch()` HEADs the wasm every 2 s, answered headers-only (body 0), so a normal boot fetches web_bg.wasm once per load. Serial fetch beats parallel.
- Freshness: nothing compares the live page with the build; check by hand after a deploy. Pages sends `cache-control: max-age=600` (platform header; the repo sets none): a browser may show an earlier build up to 10 min after deploy.
- Dev loop: localhost loads `hmr.js` (~80 fetches per module), so local request counts are not page footprint. Disable the CDP network cache before load.
- Scripts take root from `import.meta.url` or their own dir, never a machine path; Python runs as `python3 -I`. Stage archives use colon-free names (GNU tar on Windows reads `D:` as a host).
- `node scripts/check-all.mjs` is the full local gate; its entry list lives in that file, not here.
- `scripts/check-example-mods.mjs` needs `rust/target/debug/mod_check`; build it first with `cargo build -p mod-host --bin mod_check` (the gate fails with that command when the binary is absent).

## Lua mod host and sim

- A pack is one Lua module per stem; a module returns a hooks table or nothing (then its globals are hooks). `require("<name>")` takes a string literal (dependency order; cycles reported; loaded once).
- Sandbox: no string, table or file library (ordered walks use `ascending_keys`), no `string.match`, no max HP. `a, b = b, a` writes the first target before evaluating the second. Death hooks have a small step budget. `game.cmd_cast` only queues. A reused slot's armour scale, speed bounds and miss chance reset on spawn (unit_rules.lua re-sends).
- Draft: Start begins the draft (seats ready, heroes empty, `modes.picks_free`); Start again once every seat holds a hero. `modes.restrict` narrows `modes.allows`. The lobby sim does not tick: the draft clock is `game.timer("draft", 1, ...)`, so a real lobby needs the page to tick it or send ui `draft_clock {ticks}` (host key, <=64).
- Side tags: the owner fills `side` (sentinel, scourge or blank) in `scenarios/moba/hero_sides.tsv`, then runs `node scenarios/moba/tools/gen-hero-sides.mjs` to write `hero_sides.lua`. With no mode flag a tagged hero is pickable only from its side's seats (1-5 The Sentinel, 6-10 The Scourge; `modes.side_of_seat`); flagged modes ignore tags. Every hero is tagged blank for now.
- A raising hook is off for its module only; a module failing to load keeps last-known-good hooks, else is skipped; a failed build restores sim, regions and queued commands. Containment: FUEL_PER_STEP up to MAX_STEPS (`instruction_limit`); the Lua memory cap counts all modules. Wasm guests are `panic = abort`: natives run under guard_native.
- Never assign `nil` to a key that is already set in a mod table: piccolo keeps the dead key and the next grow of that table panics (`all keys must be live when table is grown`). Clear entries with `false` and test them with `if entry then` (upgrades.lua per-unit tables; spells.lua `parked_casts` and `teleports_awaiting_channel_end`).
- Step order: sim tick, zone/unit events, systems, queued commands, due timers, on_tick; commands from on_tick or timers wait a step. `on_died(unit, killer, killer_player, bounty, victim_player, killer_attributed)`: its commands apply before systems'; `feed_death` returns them unapplied.
- Hook defaults: no on_skill_up or on_cast_request allows; a Lua error or malformed on_request answer refuses. `on_state_replaced` runs after sim swap or load. `sim()` is a shared borrow that may nest; `sim_mut()` lasts one statement. `allow_cast` refuses FLAG_PASSIVE. A teleport lands only when its channel ran out.
- Natives take raw Q16.16 for positions and radii unless a `fixed` whole-unit scale is named; NaN and inf are refused. `game.effect` and `ui_event` are not hashed or replayed. Neutral player 255 is an enemy of all. `game.tree_add` refuses rectangles past 32 cells a side.
- `scenarios/moba/init.lua` lists features in hook order: `first` features hold a death so later death hooks read it unrewarded; `last` sets next tick's armour, speed bounds and miss chances; `aegis` loads first. `declare_defeat` is a no-op; the mod calls `declare_victory`.
- Determinism: peers issue commands in one order. Attack-speed bound = bonus over 100% (rule 20..700 = -80..600).
- `creep*` and `sentinel_creep*` both sit in `units_lane.osd` after every other unit (generated by `tools/gen-sentinel-creeps.mjs`). In 6.88g `sentinel_creep*` differs from `creep*` only in ranged creeps' attack point and acquire range; models are Scourge placeholders; `lanes.lua` picks by spawner owner.
- Generated-file banners (`-- Generated by ... Do not edit by hand.`) stay: `tools/emit.mjs` keeps them, so they are markers, not comments.
- Chat: sim start teams alternate by player parity, while moba_ui.json `teams` are slots 0..4 and 5..9. Chat commands use the UI teams.
- 6.88g item registry (war3map.j ZXR): AS shop/ground form, IS held form, BS muted non-owner copy, NS shop proxy unit. An IS/BS that is a hero-scepter copy or an unreachable placeholder has no item. States, courier editions and melee/ranged forms are items.
- Hero melee flag (`unit_extra(melee=True)`): 6.88g `rangeN1 <= 128` is melee; 129..200 follow Dota AttackCapabilities (web); non-6.88g heroes GUESS.
- Courier controls: the drop exemptions, the owner-return point and the per-owner filter are checked by `rust/crates/mod-host/tests/courier_owner_return.rs`. A basic courier drops an owner's item at the owner's courier creation point from anywhere (`scenarios/moba/courier_homes_688g.lua`, generated by `tools/gen-courier-homes-688g.mjs` from the 6.88g `ncop` lines); a flying courier does so only inside its base (LHV). The six `_loan` copies of the rune states are exempt (N0 via B0). Pickup moves the caller's items to the owner's creation point and then onto the owner's basic courier (SKV's Md); the courier hands them to the hero by auto-delivery (GUESS). A0OT (Change Courier Type) is blocked: one model per type. Camera zoom and rotation-lock keys are GUESS (GP-CTL-8); `js/client/zoom-check.mjs` checks only the page's own key handling.

## Abilities and trigger spells

- Ability unit stats come from unit.ini where present, else GUESS. GUESS: March of the Machines (per-second pulse, 6 robots), Visage's Familiars (40 s life), Remote Mines (radius), Ice Shards (footprint), mine hp/hull and Death Ward period, Battle Hunger stack cap, Bloodrage heal recipients, Nightmare ignoring caster hits, Stampede heroes only, Devour pays at once.
- `trigger_spells.lua`: casts with no oscraft ability are A29H, A1OB, A09Z, A3OD. Death Pact skips heroes (the cast gate does not enforce map filters). Kraken Shell sums damage from seated players' units. Map `A36D` marker = `break` status.
- Hero trigger modules: a hook has a 2500-step budget, so loops walk registries, not units. Wolf form E015 is not modelled. Burning Spear and Liquid Fire are always on.
- Lanes sharing a cargo target dir across sources get stale artifacts by mtime (stale `osdt_data` loaded as version 27): build in a lane-private `CARGO_TARGET_DIR`.
- `attack_spells.lua`: blind miss percent is in `status` p2, where 0 means 100; blind and revealed are status codes 14 and 15.
- A2ML structures from the `xZ` list are unresolved in ground-cast retargeting (`GROUND_RETARGET`, spells.lua).
- Aggro redirect (targeting.lua) ports 6.88g SWE and SSE (war3map.j 31413-31463): a hero hit by a unit that no lane player owns (players 0 and 1 own the lane creeps and towers; neutrals and allied heroes count) hands the lane creeps and towers within 500 units of the attacker to it for `aggro_hold_s` (2 s). Only heroes are registered (S4E and SYE, 31477-31482, 31591). A hero's attack order on an enemy hero runs the same redirect (SUE 31437), seen as a new attack-order target on tick: re-ordering the current target is not seen, and orders from auto-retaliation are excluded. The order path needs the enemy hero's owner to see the attacker (yU, SUE 31437). Each redirected creep gets an attack order on the hero (SLE LS), skips lane re-acquisition while the hold lasts (lanes.lua `wave_creep_step`), and is ordered back to the order it had when the hold ends or when it goes idle outside its acquire range (SPE, SKE, SQE). Not ported: SME's owner filter (any hostile creep or tower is redirected, not only players 0 and 1) and IsUnitIllusion. `died_at_tick`/`picked_at_tick` reject stale slot reuse.
- Engine slots: `game.set_heading`, `game.unit_heading` and `game.set_ability_cooldown` exist. Hoof Stomp and Reverse Polarity run their aoe, damage, stun and displace effects (`rust/crates/sim/tests/hero_area_abilities.rs`). An aoe effect's p1 bit 32 (land only) skips airborne units; Hoof Stomp sets it, as its 6.88g Ubertip names enemy land units. Reincarnation Leoric's revive, cooldown and slow are witnessed by `rust/crates/mod-host/tests/leoric_reincarnation.rs`.
- The regeneration rune (runes.lua `tick`) ends once health and mana are both full, as 6.88g QXV does; `rust/crates/mod-host/tests/rune_regen_full_health.rs` is the witness. The water sip (bottle.lua, B04A, 3 s) also ends at full health and mana, and when the rune ends, but only while a regeneration rune is running: QXV is the only watcher that removes B04A (`rust/crates/mod-host/tests/bottle_sip_full_health.rs`). Other regeneration sources run their full duration with no full-health check, as 6.88g does: the Healing Salve healer (sim healers.rs), Inner Vitality (war3map.j SEX) and reactive armour (PCR, PBR). The rune's damage check (runes.lua `hp < st.regen.hp`) has no counterpart in 6.88g QXV or P7V and is open.
- `mods/upgrades.lua` reserves each accepted request's cost in a hashed, tick-stamped counter on the requesting unit (`upg_reserve`, `upg_reserve_tick`), and the same-tick check subtracts reservations of that tick from `game.gold`, because the gold command lands one step later. Requests from a dead unit or a unit the player does not own are refused. `rust/crates/mod-host/tests/upgrade_same_tick_spend.rs` is the witness.
- Effect kind 28 (`K_RESOURCE`, once mana) keeps its number so old replays decode; kinds 24 (dispel) and 27 (illusion) are retired and refused.
- Spell damage kind: `damage` p2; `dot`/`chain` p3 = kind (0 legacy, 1 physical, 2 magical, 3 pure) + 4 * (1 + attack type index of `DAMAGE_TYPES`). Magical takes only bonus magic resistance (Hero base 25% = Hero armour column). 6.88g spell damage is `tw` (war3map.j), dt 1..11 (7 = pure, 6/11 set life). `impl-damage-attack.tsv` (hy3d project, not in this repo) tags abilities; no-script-damage ones carry attack type `spells` (hero 0.75). Other columns and `universal_damage_pct` unchecked.
- Not expressible with `damage_by` (kind 35): counts of units hit (Overwhelming Odds), Dissipate's level-multiple condition.
- Ability generators (`scenarios/moba/tools`) take numbers from SteamDatabase at `282fad29f0f74504fad465c52d197fb61f4d612b`.
- `ability_text_688g.lua` (hover text only, never read by the sim's rules) comes from `tools/gen-ability-text-688g.mjs <6.88g ability.ini>`: Name and Ubertip per level, colour codes and cooldown/mana tails stripped; a level list shares one template with per-level numbers when the wording matches.
- The `moba.osdt` in git is a stale snapshot: Pages CI rebuilds it from source with `mapexport`, so a Lua change needs no committed image. A local live witness builds it with `cargo run -p mapexport -- scenarios/moba scenarios/moba/moba.osdt` in a lane-private `CARGO_TARGET_DIR` and does not commit it.
- `abilities_688g_label_effects.tsv` maps each 6.88g DataX label to an engine effect kind (`label_status` INFERRED from the label text; NONE for cast metadata; UNVERIFIED when no kind fits). Culling Blade's 伤害 (DataA 150/250/300) is encoded as `execute` in `abilities_ruleset.osd`.
- `abilities_688g_missing.osd` is generated by `tools/gen-abilities-688g-missing.mjs` from `hero_identity_688g.tsv` (copy of hy3d `688g-data/hero-identity.tsv`), `abilities-inventory.tsv` and `abilities_688g_perlevel.tsv`: cooldown, cost, passive and target (DataB legend 0/1/2/3 = none/unit/point/unit_or_point) come from 6.88g; effects stay `[]`. Ids with no 6.88g name match are listed in `abilities_688g_missing_unverified.tsv`.

## Items and economy

- Bonuses are never stored: `change_items` applies the `item_totals` difference; `best_only` stats take the largest, the rest add.
- A recipe component must be declared before its item and cost no more.
- `tuning.osd` keys must all be present and in range or the map is refused; the duel-routes curve is unchecked. The engine holds one rank per ability slot, per-player research bits, and xp with no levels; item requests are answered by mod `ItemVerdict`.
- Attributed units: `attr_rules.txt` `key=value`; every engine key present or refused. A dead attributed unit stays dead until the mod calls `set_respawn`.
- Damage path: armour, damage response, shield, life; ability damage skips armour and applies the magic keep percent. Shields absorb before life. Roles come from unit filters, never names.
- The healing ward pays 0; every allied kill halves table xp (W_R), so `deny_xp_pct` is 50.
- Goblin's Greed (`kill_gold.lua`): stack counted before the kill (order unchecked).
- Mode HUD: panels.lua `mode_rules_box` names the active modes from TEXT.lobby.modes and their rules from TEXT.modeRules; `tools/check-mode-hud.mjs` checks every SUPPORTED mode has a label, rule, chat row and gate. Easy Mode (`em`) makes towers take 150% damage (unit_rules.lua `damage_keep`).
- Courier automation (`courier.lua` tend, every 4 ticks, GP-CTL-10/11): an idle courier stays at its team rect and returns there from elsewhere, and a courier stalled on an unreachable move returns the same way; there is no auto-follow, so an explicit Follow order is the only way a courier follows its hero, and it keeps following within 6000 units. Carried items go to a reachable owner hero within 1300 units, and an idle courier at base hands them over only while the hero is in reach. Per-owner settings `autodeliver` (on unless 0) and `secretstop` (off unless 1) are chat toggles. `game.within` takes its reach in milli-cells (not Q16.16): pass the milli constant.
- Area and delayed casts mark deny through a `timed_stat` of `S_DENY_MARK` (stat 30); unit-target casts go through `deny_mark.lua`.
- Hero acquire range: `unit_extra(<hero>, acquire=)` from unit.ini (`work/combat/timing.tsv`, hy3d project); non-6.88g heroes carry none.
- Item value sources: a value 6.88g lacks is labelled `web` (dotaconstants items.json, Dota 2 modern) or `GUESS` with its reason in items_688g.tsv stat_note.

## Waves, heroes and gold (6.88g sources)

- Lane waves: war3map.j JAE (lines 26233-26456) runs on the 30 s trigger xR. Melee per lane is 3 plus one at 849, 1759 and 2669 s (eR); ranged is 1 plus one at 2669 s (vR); siege is the ranged count per lane per side on every seventh run of xR, first at 3:00. lanes.lua matches. The 5:00 siege cadence in docs/GAME.md is reference (patches 7.06, 7.41), not 6.88g.
- Hero XP (heroes.lua): the base xp of a hero kill is wU (war3map.j, 100, 120, 140, 160, 180, then 100 x level - 320), split across the recipients. Each recipient adds 20, 15, 10, 7 or 5 (for 1 to 5+ recipients) times the victim level, plus deficit x victim xp x .23, .23, .20, .15 or .12 x .6, where deficit = max(0, victim-team xp - killer-team xp) / max(sum, 1) (D9V 14187-14200). Recipients: living allied heroes within 1325 units (0x52D) and the killer; the killer is added when alive or more than 1300 units away (0x514), and a far owner hero gets the base alone (heroes.lua share_hero_xp). Max level 25: misc.ini NeedHeroXP (xp_curve in tuning.osd).
- Assists: one definition, kill_gold.assist_group: living allied heroes within 1325 units of a hero death, plus the killer (6.88g D9V group assi, 14158-14238). It drives the A stat (heroes.lua credit_assists) and the assist gold. Creep and tower kills give no assist. The 18 s window (kill_window_s) is the damagers window for a hero killed by creeps or towers (war3map.j CGV and GDV, 13335-13353, 14515-14527).
- Roshan: the 200 team gold goes only to living heroes of the killing side (camps.lua, roshan_team_gold).
- Win: the base is the only unit with the `building` filter; when a side's base dies the rival wins (win.lua). A forfeit that ends the match publishes the win stats at once (leave.lua calls match_stats.publish(match_stats.roster())).
- Win screen gold is bounty.earned (counter st_gold_earned, added by bounty.credit and by kill_gold passive and carried-gold payouts); the reliable bank is separate.
- Post-game overview (`post_view.lua`): play-style bars are percent of the best hero this match (supporting = assists per minute, fighting = damage dealt per minute, farming = last hits per minute); pushing and per-hero averages are not tracked. The graphs tab draws line charts from one sample per full match minute (`match_stats.sample_clock`, first 60 minutes): cumulative gold, active buff count (`game.unit_buffs`), XP and kills per minute. The overview groups heroes by UI team (moba_ui.json teams); the win header names the sim winner (game.team), and the two can differ.
- Teamfight recap (`recap.lua`): two or more hero deaths within 15 s form one fight, shown for 8 s or until closed. Each side's gold swing is gained minus lost in the bounty window opened around `kill_gold.hero_died` (`bounty.open_window`/`close_window`). The death recap reports damage by source from `on_hit` records kept per victim in recap.lua (the top three attackers by damage dealt in the last `kill_window_s`, the sim keeps no totals), and names the killer the way kill credit does (`kill_gold.owner_hero`).
- `game.remove_unit` fires `on_died` with no killer, so removing a hero mid-fight records an unknown death.
- lanes.lua sync_upgrades and trees.lua heal_step walk their tables with a local ascending_keys. sync_upgrades walks only when the upgrade level changes.

## Sim core (rust/crates/sim)

- `persist.rs`: bump `STATE_VERSION` with every layout change and say what changed in the commit body. Catalog, bucket planes and scratch are not saved.
- Transient (not hashed or saved): `casting_slot`, request log, fired-behaviour queue, fx queue and hit log, cast logs, kill events, last killer, item generation counter. Hashed once set: aggro class/hold/strike target, ground items, facing. Named unit counters (`game.set_counter`, zeros omitted), per-slot item drop locks and per-unit borrowed spell blocks are hashed and saved.
- `Instant::now` traps on wasm32-unknown-unknown.
- Sim cells are 64 units, blocked when any 2x2 6.88g pathing cell is. Elevation is unused by movement, vision, combat.
- Loader: `0_names.osd` (both packs) sorts first and fixes list positions: changing a name or order changes the image, and the sim refuses a map whose lists differ. A pack resolves a definition only in files its manifest `data` lists (an effect naming a unit from an unlisted `.osd` fails `mapexport`).

## Client JS

- Language is the last channel: a state has an icon, colour or shape, and its words sit in the title or aria label (ping kinds: `js/client/ping_glyphs.js`; the minimap draws the glyph, not the text).
- A saved pack change goes two ways (`publishPackChanges`, play.js): its files go to peers as PACK_FILE frames and assets apply on the host at once; Lua and data or manifest changes queue swaps (`queuePackSwaps`), taken at the same tick as peers through SWAP, the readiness gate and `applyDueSwap`.
- The sim never reads display data (terrain heights, weight maps). Load gate (load_gate.js) never opens on a timeout. Older wasm lacks some exports (page degrades, never guesses). props.json alone names prop models.
- `recoverGame`: all tick-path Game calls stay inside the try or the rAF chain dies.
- `js/client/play.js`: the splat KTX2 path relies on `decoders.loadBasis()` warmed at module init.
- `loadSim` (play.js) starts the map image fetch before the wasm import and awaits it after `mod.default()`; `js/client/boot-overlap-check.mjs` asserts that order and rejects a serial control.
- The Lua closure (lua_closure.js, read by loadSim) comes from one request for `bundle/moba.modules.json` when Pages wrote it (scripts/bundle-lua.mjs: a JSON map of the manifest modules); without it (local dev, archives) each module is read by file. `scripts/check-lua-bundle.mjs` asserts the bundle, the closure and the Pages output path agree. Live Pages sends the .lua files uncompressed (text/x-lua) and gzips the JSON, so the bundle is 282,168 bytes on the wire against 1,167,040 for the 99 files.
- `scripts/measure-lua-wire.mjs` measures the built page's wire size by hand after a Pages build: gzip -9 and brotli -11 of the Lua closure per file and as the bundle, the wasm and the map image. No CI workflow runs it; the owner keeps checks manual and only builds in CI.
- Swaps: a peer without the image keeps its old Game.
- Hot reload (hmr.js, `/__hmr` SSE): a module exports `hmrReload(mod)`, run on the NEW instance (inputs on `globalThis.__oscraftHot`); no hook reloads the page; the wasm path concatenates ".wasm" (the Pages check reads literal ".wasm" names as root files).
- Packs: no code the page runs (.js .mjs .html .wasm .ts refused).
- mods/: one chunk per mod; bot_lib cannot require shared/xp.lua.
- `scripts/gamesparks-bootstrap.mjs` may rewrite the moba manifest's `gamesparks` block when run; manifest `data[]` stays OSDT-only.
- `rust/crates/web/site/main.js`: unit meshes are swapped for bind-pose plain meshes (`replaceSkinnedMeshes`) because SkinnedMesh vertices follow their bones, not the holder transform; without the swap every unit collapses to the origin.
- Live phase (`body[data-phase="live"]`): `game_focus.js` sends arrows to the hero keys whatever has focus (text entry excepted), sets tabindex -1 on every focusable but the chat input, and blurs on pointer down; play.html user-selects nothing in the game.
- HUD route: render3d.js has no 2D or text path (beginFrame, drawMesh, endFrame over WebGL2 mesh and splat programs), so HUD content is drawn on a 2D canvas over the game canvas, the route hud.js barCanvas, fx.js text and ui_minimap.js already use.
- The ability bar is the select panel tree (panels.lua select_tree, emitted to bar-left): a cell with unit and slot is an ability; its call is cast with args {slot}, and it has no call when dim.
- A DOM cell sends send(call, withModifiers(args, ev)) (widgets.js buildNode); play.js sendInput("ui", {call, args}) hands it to controls.lua's ui handler, which runs cast_key(slot).
- js/client/hud_canvas.js (flag ?hud=canvas) draws those cells on a canvas over the DOM row's bounding box, hides the DOM cells with a body[data-hud] rule, and sends the same call and args from its click; js/client/hud-canvas-check.mjs is the probe.
- Canvas cells take no focus or Enter (the DOM cell's tabIndex and keydown go with visibility:hidden); the sim's cast keys still cast.
- The chat text input stays a DOM element: typing needs the caret, selection and IME.
- Remaining HUD pieces: minimap (ui_minimap.js is a canvas; move its pointer handling off DOM events; commands camera_to, pointer, moba:minimap-drag); portraits (widgets.js portraitGrid; draw icons, send each portrait's call); status, messages and recap text (canvas text layout); scoreboard (panels.lua rows); menus, shop and lobby forms (DOM; need a per-panel hit layer first).
- DOM HUD commands (ui calls): cast, quickcast, skill_up, select, group_page, buyback, recap_close, toggle, talent, shop_category, quick_buy, buy, pin, build_toggle, shop_deselect, grab_all, stash_item, claim, release, remove, ready, pick, mode, fill, start; direct sends by name: camera_to (centre, minimap), pointer (minimap order), viewport and select and skill_up (moba_input).
- Local-only HUD controls send nothing: #hero-lock (heroViewLock), #map-toggle (body data-map), minimap drag (window moba:minimap-drag).
- `js/client/hero-trajectory-check.mjs` drives hero_run.js and hero_view_lock.js over a deterministic simulated frame loop with a 16 Hz sim, no GL: a uniform 60 Hz profile and a jittered 3 to 60 fps profile, with the frame time clamped to 0.1 s as play.js frameStep does (`Math.min(0.1, ...)`). It runs press, release and re-press. Its 12 and 4 cells/s hero speeds are assumed test parameters, not game data: units.osd `speed_milli` is documented as "milli per tick" (docs/GAME.md:29), and its cells/s conversion is not derived in the repo. The speed/60 focus step cap holds only at uniform 60 Hz; under jitter the gate asserts the derived cap and lag at most speed/k. Derivation, with k = LOCK_FOLLOW_RATE, h = dt, v = speed, alpha = 1 - e^(-kh): the goal moves at most v*h per frame, and the lag obeys L_n = e^(-kh)(L_(n-1) + v*h). Lag stays at most v/k by induction, since kh <= e^(kh) - 1 gives e^(-kh)(v/k + v*h) <= v/k. So the focus step alpha(L_(n-1) + v*h) is at most alpha(v/k + v*h). The measured peak ratio under jitter is 1.165. Negative controls: a dropped order, a missed release (record only), and a focus gain of 3 that must fail the derived cap. The gate proves the logic at those speeds, not the live feel, which needs a browser run at a usable frame rate.

## Scripts, generators, assets

- Generators rewrite whole files. `gen-heroes.mjs` takes a per-hero model only via `HY3D_MODEL`: an unlisted hero gets an empty model and the page refuses to start a match. `--check` variants (all `-688g`) exit 1 when the committed file differs. `gen-reference-map.mjs` overwrites map.osd with the older reference ruleset: run only on purpose.

They are data only: the sim reads ENGINE_DEFAULT (Custom) values before web. All 112 heroes with a 6.88g code (`src`) have an SLK base row; batrider's is `otbr` (dash cells).
