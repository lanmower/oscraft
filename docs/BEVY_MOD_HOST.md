# Bevy mod host: the link contract for S2

This file is the S4 contract. The Bevy server (S2) and the Bevy clients hold the piccolo mod host through the `ModRuntime` port in `rust/crates/mod-host/src/runtime.rs`. `ModHost` implements the port by delegation, so the scripts keep their API: the globals in `HOST_GLOBALS` and the hooks in `EVENTS` are checked by `scripts/check-mod-host-port.mjs`.

Status: S4 Phase A is code and tests. The Rust port and the test migration are written and not yet compiled; compile and `cargo test -p mod-host` are Phase B. The Bevy side that calls the port is S2 work (the bevy peer), so the live link into the Bevy server and clients is not in this change.

## Port

`ModRuntime` declares the 30 host calls a Bevy host needs. Each is a delegation to the inherent `ModHost` method of the same name.

- Setup: `set_sim`, `load_source`, `load_mods`, `load_file`, `reload`, `load_state`.
- Tick: `advance`, `cast_allowed`, `cmd_spawn`, `fire_trigger`, `player_joined`, `player_left`.
- Input and frames: `dispatch_action`, `pointer`, `frame`.
- Output: `take_ui`, `flush_ui`, `state_line`, `state_int`, `state_bool`, `units`, `unit_kind`, `players`.
- Diagnostics: `hook_errors`, `disabled_hooks`, `version`, `counters`, `events`.
- Sim access: `sim`, `sim_mut`.

The mod-host tests (`rust/crates/mod-host/tests/*.rs`) open their host through the port (`-> impl ModRuntime`). They call only the port's methods (`sim`, `sim_mut`, `advance`, `dispatch_action`, `load_mods`, `take_ui`, `load_source`, `hook_errors`, `cast_allowed`), which the check enforces.

## Schedule

The sim runs at 16 ticks per second (D2). The Bevy host calls the port on this schedule:

- Server, FixedUpdate, once per sim tick: apply accepted client orders through `dispatch_action` and `cast_allowed`; call `advance` once; call `player_joined` and `player_left` on join and leave; read `state_line`, `units`, `unit_kind` and `players` for the STATE and DELTA frames; drain `take_ui` to the clients.
- Client, Update, once per render frame: call `frame` with the frame time for the read-only `on_frame` hook; forward input as `pointer`; drain `take_ui` into the HUD.
- Client sim copy: each client runs its own `ModRuntime` on a sim copy that the same accepted orders keep in step, and compares its state hash with the server's each tick (D4). A mismatch is a desync.

The server is the only place that decides which orders apply (D3, host-authoritative).

## Not on the port yet

`feed_death` (and its `Death` and `Cmd` types) and `emit_unit` stay off the port. Their types are defined in the piccolo module, and the S2 server adds them to `ModRuntime` in the same change that first calls them. This keeps the Phase A change to signatures that already exist and are read from source.

## Splice anchors

The generated blocks in `scenarios/{moba,moba-acronyms,bota}/attr_rules.txt` are spliced between `# BEGIN generated by scenarios/moba/tools/gen-heroes.mjs` and `# END generated by scenarios/moba/tools/gen-heroes.mjs`. The generator appends a second block when the END anchor is missing, so `scripts/check-attr-rules-anchors.mjs` fails on a missing, duplicated or misplaced anchor. `duel-routes` is not generated and must carry no anchor.

## Witness for S4 (Phase B)

- `cargo test -p mod-host` passes through the port.
- `node scripts/check-mod-host-port.mjs` and `node scripts/check-attr-rules-anchors.mjs` pass, with their red cases.
- The run against the Bevy host (the S2 server and client building the port) is recorded when S2 lands; until then the tests run against `ModHost` through the port.
