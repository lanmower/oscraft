# 25. Engine data plan

How the plan's tables become engine data, and how the plan's markdown tables are generated from the same data. Status: UNVERIFIED design note. Written 2026-10-25 against plan files 00 to 24 and 26 as they stood then (file 22 was searched, not read in full), and revised 2026-10-27 after the plan audit. Resolved items carry the revision date. Repo facts carry their path. Every number that is not a repo fact is UNVERIFIED.

## A. What the repo does today

### A1. How content is defined (question a)

- **Packs.** A game is a directory with `manifest.json` at its root. Data is `.osd` source, compiled by `mapexport` into one `.osdt` image. Rules are Lua modules listed in the manifest. `.tsv`, `.json` and `.txt` are allowed as tables, UI and key=value rule files. `.js`, `.mjs`, `.html`, `.wasm`, `.ts` and `.map` are refused on load, edit and transfer (docs/MODDING.md, docs/SCENARIOS.md).
- **Packs present.** `scenarios/moba` (the match) and `scenarios/duel-routes` (a routes test). The engine names no genre.
- **Units.** `scenarios/moba/units.osd`, `units_heroes.osd`, `units_extra.osd`, `units_summons.osd`, `neutral.osd`, `waves.osd`. One line per unit: `unit(name, health, speed_milli, radius_milli, ...)`.
- **Abilities.** `scenarios/moba/abilities.osd` (`ability(...)` with `effect(...)` handles), twelve generated batches `abilities_688g_b01.osd` to `b12.osd`, and `abilities_ruleset.osd`. Tables beside them: `abilities_688g.tsv`, `abilities_688g_perlevel.tsv`, `abilities-inventory.tsv`. Engine form: ABIL, SKIL and AXTN records, which carry per-rank damage, cooldown and energy (rust/crates/data/FORMAT.md).
- **Items.** `scenarios/moba/items.osd`, with the call `item(name, cost, stats={}, ability=, components=, consumable=, ...)` documented in the file header. Engine form: ITEM record, 192 bytes, 38 fixed stat slots, stock and restock fields (FORMAT.md).
- **Rules.** Lua modules in `scenarios/moba/`: camps, clock, kill_gold, lanes, levelup, store, talents, skills, win, respawn (core/), protection, taunt, upgrades, targeting, unit_rules, panels, controls, effects. Behaviours in `behaviours.osd`. Engine calls a modifier a status effect and an upgrade a tech level (both renames pending in docs/NAMING.md).
- **Economy and tuning.** `economy.osd` (one `economy(...)` call), `tuning.osd` (one `tuning(...)` call, including an `xp_curve`).
- **Map.** `map.osd` (grid, paint, start, spawn), `routes.osd`, `doodads-688g.tsv`, `starts-688g.tsv`.
- **Derived tables.** `heroes_688g.tsv`, `creeps_688g.tsv`, `doodad-types-688g.tsv`, `slot-models.tsv`, `attr_rules.txt` (key=value, read by `game.rule`), `moba_ui.json` (controls and effect kinds).
- **Generators.** `scenarios/moba/tools/*.mjs`: gen-heroes, gen-items, gen-abilities, gen-ability-fx, gen-buff-fx, gen-reference, convert-688g-map, place-doodads-688g and others. `scripts/apply-heroes-688g.py`, `apply-abilities-688g.py`, `apply-creeps-688g.py`. The established pattern is TSV to `.osd`, and `.osd` to a generated Markdown view (`docs/REFERENCE.md` is generated by `gen-reference.mjs`).
- **Name rule.** Engine names match `[a-z][a-z0-9_]*`, at most 255 bytes (FORMAT.md, Names).
- **Absent.** No Clout, Trend, boost, Ratio, Repost, Stan, draft-mode or archetype data exists in the engine or the packs. Literal search for "clout" and "trend" in rust/, mods/, scenarios/, scripts/ and docs/ returned zero hits.

### A2. What the build pipeline does with that data (question b)

- `scripts/dev/stage.sh`: builds wasm when the pkg is missing, runs `mapexport` for each pack in a fixed loop (`for p in moba duel-routes`, line 16), then calls `scripts/layout-site.sh`.
- `scripts/layout-site.sh`: copies `js/client`, the wasm pkg, `scenarios/` (removing each pack's `tools/`, line 26), and `mods/` into the site. It packs `scenarios/moba` into a split archive unless `SKIP_PACKS=1`. Its only content check is for `scenarios/moba/manifest.json` and `moba.osdt` (line 33). It does not copy `247420/`.
- `.github/workflows/ci.yml` (lines 88 to 90) and `pages.yml` (lines 90 to 92) build `mapexport` and name both packs explicitly.
- `.github/workflows/tests.yml` (lines 130 and 152 to 165) runs `mapexport` twice and compares the bytes.
- `scripts/pack-package.mjs`: `--build` runs `mapexport` first; archives are split above 25 MiB.
- `scenarios/moba/tools/check-fx.mjs` runs in CI (docs/MODDING.md).
- `rust/gate/` holds check modules (checks.rs, mechanic_checks.rs, spell_checks.rs, mod_checks.rs). Not read for this note.

Consequence: a second pack needs edits in `stage.sh`, `pages.yml` and `ci.yml`. If one edit is missed, `layout-site.sh` still succeeds and ships a pack with no `.osdt`, because it checks only the moba pack.

### A4. Does the wire layer limit where game data can live (question d)

- Data lives in the pack directory and reaches the browser through the Pages site. Peers get data only from the host. The host edits, Save sends `PACK_FILE` frames, and a file over 256 KiB travels by content hash through `PACK_WANT` (docs/MODDING.md, docs/WIRE.md).
- A data change changes the image hash (FNV-1a over the image bytes). The host announces it with `SWAP` at a tick, each peer answers `SWAP_READY` or `SWAP_NOT_READY` for that tick and hash, and the host can drop it with `SWAP_CANCEL` (docs/WIRE.md, frames 14, 17 to 19).
- Limits that touch data: a START seat's pick name is at most 32 bytes and its owner at most 64 (frame 10). Unit records carry a `u16` kind, which is a position in the image, and at most 4,096 units per frame. ROSTER carries at most 10 players. An ACTION body is at most 4,096 bytes.
- Consequence: data can live in a pack and in Pages, but it cannot be fetched from a server and every peer must hold a byte-identical image. Generated data must therefore be byte-stable.

## 2. Single source of truth and generation direction

**Canonical data.** One TSV per table, UTF-8, LF, header row, stable id column. The canonical files are `scenarios/brainrot/data/*.tsv`, which the pack ships, so they hold Brainrot names only. Headers, as an illustration:

```
heroes.tsv     hero_id slug name archetype_id attr range launch status
abilities.tsv  hero_id slot slug name kind tier dmg_r1 dmg_r2 dmg_r3 dmg_r4 cd_r1 cd_r2 cd_r3 cd_r4 mana_r1 mana_r2 mana_r3 mana_r4 ult_gate_1 ult_gate_2 ult_gate_3 status
items.tsv      item_id slug name kind tier cost components stats active stock restock_s drop_on_death flavor status
```

**Generated outputs, one direction only.**

1. `scenarios/brainrot/*.osd` and a key=value rules file, written by `scenarios/brainrot/tools/gen.mjs`. The `tools/` folder is excluded from Pages by `layout-site.sh` line 26.
2. The markdown tables in `247420/plan/NN-*.md`, written by the same tool. It finds each table by its heading text. It does not use HTML comment markers, because the comment rule in the global instructions (INVARIANT 3) applies to comments in files.
3. A drift check: the tool regenerates everything and fails if the tree differs. This copies the determinism check already in `tests.yml`.

Direction: TSV to `.osd`, TSV to the rules file, TSV to plan markdown. Nothing flows back. Before the first generation the plan markdown is the source, so the first TSV is produced once from it and reviewed. After that cutover, a number is typed only in the TSV.

**Rules for ids and names.**

- `hero_id`, `item_id`, `archetype_id` and `modifier_id` are append-only numbers. They are never reused. The generator sorts by these ids, never by plan order.
- Engine name = `slug`, which must match `[a-z][a-z0-9_]*`, be at most 32 bytes for hero slugs (the wire's pick-name limit), and be unique within each name list.
- A rename changes the `name` column only. Changing a `slug` is an engine rename, done once, in the generator.
- The `status` column is `UNVERIFIED` (default), `checked:<repo path>` (only when a 6.88g value matched locally), or `design` (set by the balance pass). The generator prints it next to every number, which is the AGENTS.md rule that unknowns stay marked in the file that holds the value.

**Units.** Numbers are typed in plan units: seconds, percent, gold and game units. The generator converts. Seconds become ticks at 16 per second, rounded (3.8 s is 60.8 ticks, so 61). Percentages become Q16 (65536 equals 1.0). Distance is in game units, the engine whole-unit scale: 1 game unit is 125/8 milli-units (section 20, decision 24).

**Pack location.** Option A is `scenarios/brainrot/`. It ships automatically through `cp -r scenarios`, but it needs `mapexport` lines added to `stage.sh`, `pages.yml` and `ci.yml`. Option B is `247420/pack/`, which needs a copy line in `layout-site.sh`. Use B for the first slice; move to A when the pack wiring lines land.

## 5. Risks and open questions

### Risks

- **R1. The parity map stays out of packs and Pages.** `layout-site.sh` copies `scenarios/`, `mods/` and `js/client/`, not `247420/`, so the map does not ship today.
- **R2. The plan is tracked but outside the build.** `plan/` and `internal/` are tracked in git; `layout-site.sh` does not copy them. Drift checks can read them in CI, but generated plan tables are never shipped.
- **R3. Pack wiring is hard-coded.** `stage.sh` line 16, `pages.yml` lines 91 to 92 and `ci.yml` lines 89 to 90 list the packs by name. A new pack without these edits gets no `.osdt`, and `layout-site.sh` still succeeds because it checks only moba (A2).
- **R4. Ultimate gates differ.** FORMAT.md line 307 fixes ultimate gates at 6, 12 and 18. Plan sections 7 and 9 say 6, 11 and 16. This needs a format decision (which bumps the version) or a plan change.
- **R5. Time units do not divide evenly.** Ticks run at 16 per second (REFERENCE.md line 5), and FORMAT.md requires durations as integer ticks. The plan's 3.8 s per level gives 60.8 ticks. The generator needs a written rounding rule.
- **R6. Clout, Reach, Stan, Ratio, Repost and global Trend modifiers have no data slot.** ITEM_STATS is fixed at 38 entries (FORMAT.md line 298), and plan decision 9 says Clout is never a stat, so these are Lua hooks. AXTN modifiers (8 per ability, FORMAT.md line 328) cannot express a global modifier. Each hook runs under a 2,500-step budget (docs/MODDING.md line 47), which constrains per-tick Reach recalculation.
- **R7. Filter bits are capped.** FNAM allows at most 15 bits (FORMAT.md line 376). Twelve archetype filters plus role filters can exhaust that. Keep archetype as a data column and use filter bits only for targeting.
- **R8. Ids are positions.** Item ids are record indices, and ability indices follow declaration order (FORMAT.md). Unit `kind` is a `u16` position on the wire. Inserting a row renumbers everything after it, which makes a new image hash and a SWAP at a tick (docs/WIRE.md). Generation must keep ids stable, as section 2 says.
- **R9. Output must be byte-stable.** `tests.yml` compares two `mapexport` runs byte for byte. The generator must sort, use LF, fix float formatting and write no timestamps.
- **R10. FORMAT.md is internally inconsistent.** It says "the reader requires all twenty-eight tags" (line 28), but the header, the table and the rule at line 17 all say 27. Fix the sentence when the file is next edited.
- **R11. Contradictions found on 2026-10-25, resolved on 2026-10-27.**
  - The component 1 band is 50 to 100, the finished Tier 1 band is 65 to 300, and assembly is explicitly discounted (file 11).
  - Spoiler Tag moved to Tier 1 at 75 gold (file 11).
  - Drain Blade, Grindset and Lite Plan gained roster rows; Drain Blade and Lite Plan gained stats rows (file 11).
  - File 12 now names eight Trend modifiers, with check rows for all eight.
  - Files 10 and 15 still use short archetype labels ("Algorithm", "Ghost", "Notification", "Hermit") while files 09, 14 and 19 use the full names. The TSV `alias` column carries both.
  - Rebrand is an action, not an item (file 05); file 26 matches.
  - `00-index.md` lists files 00 to 26 and its links resolve (checked 2026-10-27).
- **R12. The source is moving.** During this session files 06, 11, 12 and 14 changed, and files 22, 23, 24 and 26 were added. Generators must find tables by heading and must reject duplicate or missing headings.
- **R13. The 6.88g archive is absent.** The convert tools cannot run here, so the derived tables cannot be regenerated from the source. The local checkout and origin/main matched on 2026-10-27.
- **R14. Local changes are uncommitted.** `scripts/dev/stage.sh` and several `js/client` files were modified at session start. The `stage.sh` facts in A2 come from the working tree.
- **R15. Measured mismatch in the scenario data.** The convergence report counts 366 differing field comparisons (docs/CONVERGENCE_688G.md section 3). The scenario stats are therefore not 6.88g values even where names pair.
